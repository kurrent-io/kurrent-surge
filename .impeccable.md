## Design Context

### Users

.NET developers (expanding to Go, Java, Python, Rust) building event-sourced systems on the Kurrent platform.
They arrive at the docs to learn the SDK API, troubleshoot integration issues, read changelogs, and understand
architectural decisions. Many come from the EventStoreDB community and expect technical depth without hand-holding.
Context: working in IDEs, switching between code and docs, often under time pressure to ship.

### Brand Personality

**Technical, Confident, Precise.** Kurrent is an engineering-grade platform and the docs should reflect that.
No marketing fluff in technical content. The brand projects competence and reliability — it earns trust through
clarity, not decoration. The Ouro mascot adds a human, approachable counterpoint to the otherwise serious tone.

Three words: **confident, precise, modern.**

### Aesthetic Direction

**Theme**: Dark-first with a polished light mode. The Stripe "too white" feel is explicitly rejected — lean into
the dark palette (background #080b0d in dark mode) with the Plum (#631B3A) and supporting colors as accents.

**References** (what to aspire to):
- **Vercel** (changelog, blog, academy) — clean typography, excellent information hierarchy, premium feel
- **Stripe** (docs structure, information density) — but darker, not the washed-out white theme
- **Linear** (docs, /now page) — dark-first confidence, bold typographic hierarchy, product-led
- **Slack Engineering** / **Uber Engineering** blogs — engineering content presentation, document-style posts

**Anti-references**: Generic documentation themes with no personality. Overly light/white themes with no depth.
Cookie-cutter developer portals that all look the same.

**Platform**: Migrating from VuePress 2 to Astro Starlight for a unified SDK docs site covering all language
SDKs (.NET, Go, Java, Python, Rust). Content includes API docs, blogs, postmortems, feature specs, research
docs, and per-component changelogs (Client, Processors, Connectors).

### Design Principles

1. **Content density over decoration.** Developers scan — optimize for information retrieval, not visual
   spectacle. Every pixel of chrome should earn its place. Vercel-level restraint.

2. **Dark-first, light-capable.** Design in dark mode first, then adapt to light. The dark palette is the
   brand's natural home. Light mode should feel intentional, not default.

3. **Typographic hierarchy does the heavy lifting.** With Solina as the display face and a clean body stack,
   the type system should create visual structure without needing excessive color or ornamentation.

4. **Plum as punctuation, not wallpaper.** The brand color is powerful in small doses — links, active states,
   accent lines, code annotations. Full plum backgrounds are for hero moments only.

5. **Pragmatic accessibility (WCAG AA).** Hit 4.5:1 contrast for body text and interactive controls. Decorative
   elements and large display type get more freedom. Never sacrifice readability for brand aesthetics.
