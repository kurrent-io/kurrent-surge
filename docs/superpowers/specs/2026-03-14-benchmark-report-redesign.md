# Benchmark Report HTML Redesign

Redesign the static HTML dashboard generated by `tools/benchmark-report.cs` from a DaisyUI/Tailwind template to a
hand-crafted "Mission Control + Bento" aesthetic. The report is a single-file, self-contained HTML document that
visualizes BenchmarkDotNet JSON results.

## Design Direction

**Mission Control + Bento hybrid**: a dark operations console base (monospace-heavy, glowing accents, dense data)
combined with Apple-inspired bento stat cards (bold type, rounded cards, gradient elements). The tone is "technical
dashboard for engineers" rather than generic SaaS analytics.

Key aesthetic principles:

- Dark-first with a light alternate theme
- JetBrains Mono as the primary font; system sans-serif for display headings and stat values
- Colored glow accents (green, blue, amber, red) for semantic meaning
- Uniform 5px border radius across all elements
- Dense data presentation; no wasted space

## Tech Stack

### Drop

- DaisyUI 5
- Tailwind CSS (browser build)

### Keep

- Chart.js 4 (CDN)
- Lucide icons (CDN)

### Add

- JetBrains Mono from Google Fonts
- Hand-crafted CSS with CSS custom properties for theming

The page remains a single self-contained HTML file with no build step. All external resources are CDN links.

## Page Layout

Top to bottom, the page is structured as:

1. **Sticky header** with frosted glass effect (`backdrop-filter: blur(16px)`)
2. **Environment panel** (2-column grid of host info cards)
3. **Bento stat cards** (4-column grid of aggregate metrics)
4. **Per-class benchmark sections**, each containing:
   - Section header with status dot, collapse chevron, class name, and benchmark count
   - Group-by pills and search/jump controls (on the first section)
   - Data table with sortable columns and pagination
   - Collapsible charts disclosure with performance bar chart and distribution plot
5. **Keyboard hints bar**
6. **Legends card** with metric and time unit definitions
7. **Footer** with generation timestamp

## Components

### Sticky Header

- Title ("Kurrent.Client Benchmark Report"), mode badge (`single-run` or `comparison`), benchmark count badge
- Generation timestamp
- Controls row: search input (expandable, `flex: 1`), jump-to dropdown, theme toggle button

### Environment Panel

Two cards in a 2-column grid:

- **Machine card**: OS, CPU, Cores (physical/logical), Architecture
- **Configuration card**: Runtime version, BenchmarkDotNet version, Toolchain, Job config (warmup count, iteration
  count, build configuration)

Each card has an uppercase label with icon and a key-value grid. Data sources: `BdnHostInfo.*` and `JobConfig.*`.

### Bento Stat Cards

Four cards in a 4-column grid showing aggregate stats:

- **Fastest** (green glow): method name, formatted mean time
- **Slowest** (red glow): method name, formatted mean time
- **Peak Alloc** (amber glow): single highest allocation value with the method name that produced it
- **Throughput** (blue glow): highest ops/s with method name

Each card: uppercase label + icon, large display value (30px, 800 weight), detail line showing the method name.

### Section Headers

Each benchmark class (`BenchmarkEntry.Type`) gets its own collapsible section. The header contains:

- Animated status dot (green pulse)
- Collapse/expand chevron
- Class name (e.g., `ReadStreamBenchmarks`)
- Benchmark count label

Clicking the header toggles the section body visibility.

### Data Table

Sortable table inside a bordered container with columns in this order:

| Column | Content                                         |
| ------ | ----------------------------------------------- |
| Method | Method name (bold) + parameters if present      |
| Count  | Iteration count from `Measurements` array       |
| Mean   | Formatted time value                            |
| Ops/s  | Operations per second                           |
| Dist.  | Inline sparkline histogram (CSS vertical bars)  |
| Error  | Confidence interval margin                      |
| StdDev | Standard deviation                              |
| P95    | 95th percentile                                 |
| Alloc  | Allocated bytes with color-coded badge          |
| Rank   | Numeric rank badge (green/blue/amber/gray)      |

Sort indicators: clicking a header toggles asc/desc. Active column gets a blue-tinted background and visible sort
arrow icon. Headers use a flex `.th-inner` wrapper for icon alignment.

**Alloc badge thresholds:**

- `alloc-zero`: 0 bytes (muted gray)
- `alloc-low`: < 1 KB (green)
- `alloc-mid`: 1 KB to 100 KB (amber)
- `alloc-high`: > 100 KB (red)

**GC columns** (Gen0, Gen1, Gen2): conditionally shown when any benchmark in the group has non-zero GC collections.
Displayed as simple numeric cells.

### Pagination

Below the table inside `.table-wrap`. Shows "Showing X-Y of Z" on the left, page buttons and page-size selector on
the right. Default page size: 5; options: 5, 10, 25.

### Charts Disclosure

Collapsible section below the table, toggled via a click bar with chevron rotation animation.

Contains a 2-column grid (3fr / 2fr):

- **Performance bar chart** (Chart.js): horizontal bars showing the selected metric per benchmark. Metric switcher
  pills (Mean, Ops/s, P95, Alloc) plus a log-scale toggle. Switching metrics replays the bar animation.
- **Distribution plot (box-whisker)** (CSS): per-benchmark rows showing P0-P100 range, IQR box, and median line.
  Each row has a label, visual bar, and numeric value. Data from `BdnStatistics.Percentiles`. This is distinct
  from the inline sparkline histogram in the table's Dist. column.

### Keyboard Hints Bar

Horizontal bar showing keyboard shortcuts: `j`/`k` navigate rows, `/` search, `Enter` expand, `Esc` collapse.

### Legends Card

Two-column grid with:

- Left column: metric icons and descriptions (Mean, Ops/s, Error, StdDev, P95, Gen0/1/2)
- Right column: time unit abbreviations (ns, us, ms, s) with conversion factors

## Comparison Mode

When `ReportData.IsComparison` is true, the report adjusts its presentation:

- **Mode badge** in the header switches to `comparison` with a warning-colored badge
- **Data table** gains additional columns after the standard set:
  - Delta (%): percentage change from baseline, color-coded (green for improvement, red for regression)
  - Classification badge: "Regressed", "Improved", "Unchanged", or "New"
- **Bento stat cards** adjust to show comparison-relevant aggregates (regression count, improvement count)
- **Regression summary**: if regressions exist, a summary section lists each regression with method name, current
  vs baseline values, and delta percentage

The comparison data comes from `ReportData.Comparisons` (list of `ComparisonEntry`), each containing `Current`
and `Baseline` `BenchmarkEntry` instances, `DeltaPercent`, and `Classification` string.

The visual treatment for comparison mode follows the same Mission Control aesthetic. Delta percentages use
accent-red for regressions, accent-green for improvements, and text-muted for unchanged/new.

## Interactive Features

- **Theme toggle**: switches `data-theme` attribute on `<html>` between `dark` and `light`. Rebuilds Chart.js
  charts to pick up new text/grid colors.
- **Search**: dynamic text input that filters table rows by method name. Slash key (`/`) focuses the input.
- **Jump-to dropdown**: `<select>` populated with benchmark class names for quick scroll navigation.
- **Group-by pills**: filter/group benchmarks by class. Labels match the grouping dimension available in
  `BenchmarkEntry.Type`. Active pill highlighted blue.
- **Column sorting**: click table headers to sort asc/desc. Active sort column has blue background tint.
- **Pagination**: page navigation with configurable page size.
- **Section collapse**: per-class sections are independently collapsible via their section headers.
- **Charts toggle**: collapsible charts section with smooth max-height/opacity transition.
- **Metric pill switching**: on the performance chart, clicking Mean/Ops/s/P95/Alloc reconfigures and re-animates
  the chart.
- **Log scale toggle**: switches the bar chart x-axis between linear and logarithmic scale.
- **Keyboard navigation**: `j`/`k` for row navigation, `/` for search focus, `Enter`/`Esc` for expand/collapse.

## Animations

### Entry Animations (CSS)

- `fadeSlideUp`: opacity 0 + translateY(12px) to normal. Used on cards and sections with staggered delays.
- `growRight`: scaleX(0) to scaleX(1). Used on distribution bars.
- `fadeIn`: simple opacity transition. Used on keyboard hints and legends.
- `pulseGlow`: pulsing box-shadow on the status dot.

### Chart Animation (JavaScript)

Custom `requestAnimationFrame` loop because Chart.js built-in `animation.delay` does not produce visible per-bar
stagger. Implementation:

1. Set all bar values to 0 and call `chart.update('none')`
2. For each bar, schedule a delayed RAF loop with `easeOutQuart` easing
3. Each bar starts `staggerMs` after the previous one
4. Total duration ~2200ms with 250ms stagger between bars
5. Animation replays when switching metric pills

### Hover/Interaction

- Table rows: background shift on hover
- Bento cards: border-color transition on hover
- Buttons/pills: border-color and background transitions (0.15s)

## Implementation Scope

### What Changes

- The `GenerateHtml` method in `tools/benchmark-report.cs` (approximately lines 464-1758) gets rewritten to emit
  the new HTML/CSS/JS template
- The string interpolation structure remains the same (C# `$$"""..."""` raw string literals injecting data)
- A new JSON data blob must be serialized alongside the existing `benchmarkJson` to carry per-benchmark measurement
  arrays and percentile data to the client-side JavaScript. The raw `BdnBenchmark.Measurements` and
  `BdnStatistics.Percentiles` are not fields on the processed `BenchmarkEntry` record. Two options:
  1. Serialize a separate `measurementsJson` map (keyed by `CompositeKey`) containing the `Measurements[].Value`
     arrays and `Percentiles` objects from the raw `BdnBenchmark` data
  2. Extend `BenchmarkEntry` with optional measurement/percentile fields

  Option 1 is preferred because it avoids changing the existing model and keeps the measurement data separate from
  the summary statistics.

### What Stays the Same

- All C# models (`BdnRoot`, `BenchmarkEntry`, `ReportData`, `ComparisonEntry`, etc.) unless option 2 above is chosen
- The CLI interface (`ReportCommand`, argument parsing)
- Data transformation logic (parsing, ranking, comparison)
- The JSON summary output
- File output behavior (write HTML to disk, optionally open browser)
